# WinShun Packages

[中文](README.md) · [Design](plugin-design.en.md) · [UI specification](UI-SPEC.en.md) · [Test plan](TEST-PLAN.en.md)

`ra9fael.packages` is a WinShun package-manager plugin: view, install, remove, reinstall and upgrade Scoop and WinGet packages in one window. Current version **0.4.12**.

It runs with **ordinary user rights** (no `elevated` permission). Queries only return results; every change needs an exact identity, a reviewed plan, and explicit confirmation before it is queued. When WinGet or an installer needs administrator rights it requests UAC itself; the plugin never elevates, de-elevates or retries with different privileges.

## Implemented

- **Installed**: WinGet and Scoop inventories in one list, never merged when names collide; backend-recorded rows are distinguished from merely enumerated ones (ARP/MSIX); local filtering.
- **Discover**: asynchronous search that discards late replies; a search hit whose scope WinGet does not report must have "current user / all users" chosen in review before it can be confirmed.
- **Updates**: target versions from backend evidence, respecting `winget pin list` pins/holds.
- **Tasks**: one authorisation per change, serial per manager; phases `install/uninstall › verify` with the state checked afterwards rather than trusting the exit code; failure, partial failure and unknown outcome are distinct.
- **Diagnostics**: full command line and backend output in the task log (paths and tokens redacted); `0x8A15007D` (elevated process, user-scope package) and `0x87AF0008` (WinGet user database not writable) get explicit explanations.
- **Caches**: inventory, updates, search results, package details, pin list and probe verdict are cached separately on disk and reused under `refreshMinutes` with their own invalidation rules; a failing backend does not force a rescan of the other.

## Permissions

| Permission | Purpose |
|---|---|
| `ui` | plugin window, theme and language |
| `processes` | run `winget` / `scoop` (PowerShell) and read their output |
| `network` | WinGet / Scoop download packages and source data; the plugin makes no extra requests |
| `clipboard:write` | copy IDs, logs and paths through the host's `clipboard_copy` |
| `files:read` / `files:write` | read and write only the plugin's own data folder (`%LOCALAPPDATA%\WinShun\plugins\ra9fael.packages.data`) for caches |

## Build and release

Requires Windows x64, MSVC and Qt 6.12 (the host's shared Qt; the plugin ships no Qt DLLs):

```powershell
cmake -S . -B build\dev2
cmake --build build\dev2 --target packages
python tools\package.py --out dist\release-0.4.12   # produces <id>-<version>.wsplugin
```

The release asset is named `<id>-<version>.wsplugin` and attached to the GitHub Release for the matching tag; the registry entry is generated by `WinShun-plugins` `tools/entry.py` from that asset. This is a C++ plugin on the host's shared Qt, built locally from a fixed commit, so it does not use the generic script-packaging release workflow.

## Acceptance requirements (specification appendix)

The PKG-Fxx entries below are the original requirements and acceptance criteria; they remain the behaviour specification. See "Implemented" and the [changelog](CHANGELOG.en.md) for progress.

### Scope and entry

The proposed WinShun keyword `packages` opens a separate window on Installed. Navigation is Installed / Discover / Updates / Tasks with All / Scoop / WinGet filters. Queries only return results; changes require selecting an exact package, reviewing a refreshed plan, confirming, and queuing. Either backend remains usable when the other is missing. Managers, PowerShell modules and other optional dependencies are never installed automatically.

P0 covers normal-user installed / search / details / update-list, selected install / uninstall / reinstall / upgrade, and the queue. P1 covers read-only source/bucket diagnostics, recovery assistance and explicit metadata maintenance. Full source/bucket/pin/hold management is P2. P0 must already read and respect existing pins/holds. P0 excludes implicit upgrade-all, cross-manager migration, automatic repair, automatic agreement acceptance, default purge and automatic elevation.

## Manager semantics and reinstall boundaries

Official WinGet documentation lists search / list / show / install / upgrade / uninstall / repair, not reinstall. Never generate `winget reinstall`; repair is not reinstallation. Do not claim universal `--output json`. Optional structured paths need independent version/deployment validation.

Scoop source revision `e6aa3b366bdee8ed138c1e0f7b85192ebdd35d0f` establishes that argument-free `update` updates Scoop and buckets; `update <app>` upgrades an app and may first synchronize the manager/metadata; `install` has no force option; `update --force` does not guarantee the original version, and an @version pin can resolve to bucket HEAD; `reset` rebuilds links, shims and environment state without downloading/reinstalling the package. See [design facts and capability table](plugin-design.en.md). Reading source is not a local runtime test.

Reinstall planning first resolves exact identity and version. If the original version is unavailable, stop or require explicit alternative-version selection and reconfirmation. Before removal, verify a supported acquisition/staging mechanism, manifest, architecture, dependencies, installation material integrity and licensing. Disable reinstall when this cannot be done; never remove first and then search for an installer. Preflight cannot guarantee later installation, data retention or automatic rollback. No default purge; installer/uninstaller behavior can still delete data.

Open decisions: installer/UAC broker viability inside the host Job; concrete supported manager versions/language fixtures; optional WinGet API dependencies; reliable original-version material prefetch; exact scope/uninstall resolution for unknown/observed entries; performance/capacity calibration. All executable capabilities remain unaccepted; design approval is required before implementation.
