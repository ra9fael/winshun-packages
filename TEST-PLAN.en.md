## Scope and isolation

36 stable test IDs cover 30 PKG-Fxx requirements. Only documents exist; every row is not executed. Reading documentation/official source is not a dynamic test pass. This task runs no managers, probes or software install/uninstall operations and authors no test scripts.

Future L0 covers static manifest/packaging and documentation checks; L1 is OS-header-free pure logic; L2 uses fake hosts/backends; L3 is real-host round trips and gates implementation acceptance; L4 uses an unlocked VM desktop, real input and installer interaction; L5 covers calibration/release. All dynamic tests, including ordinary queries and performance sampling, use isolated restorable VMs with independent accounts/sources/data directories, no user credentials/shared user folders, and disposable packages. Installer/UAC cases use dedicated snapshots and never touch existing user software, configuration or documents. Test operators explicitly accept any necessary official-source terms inside the VM; no automatic consent.

Record Windows/host version, normal/administrator host, exact backend version or Scoop revision, invocation kind, locale/encoding, scope, installer type and optional API dependencies. Passing one version/language/installer never establishes universal support. Administrator scopes stay disabled until L3/L4 probes pass. Do not 鈥渇ix鈥?failed probes by elevating the whole plugin or removing its Job.

## Execution and evidence gates

Future records include actual steps, expected/actual differences, version matrices, time and evidence files; 鈥渓ooks fine鈥?is not an assertion. Even L0/T01 has not been executed as a formal test. Delivery checks in this task are not acceptance evidence. L1/L2 fake success does not prove real installer compatibility. A path enters the capability allowlist only after L3 and L4 pass; uncovered installers/scopes/versions remain unsupported. P1/P2 cases define scope/future gates rather than implementation in this task.

Network downloads/staging during material preflight are side effects and require an acquisition-plan confirmation first. Tests must establish that details do not trigger downloads and uninstall never precedes material discovery. After L5 peak/headroom measurements, update design/UI/capability records with the rationale. If host budgets cannot support them, degrade/disable rather than editing host configuration. Post-test cleanup, snapshot restoration and disposable-package removal occur only inside the VM under the future test procedure; none run now.

Open decisions: exact supported versions/fixtures, material prefetch, Job/UAC/proxy viability, unknown-scope/observed exact uninstall, external activity detection and performance/capacity. This plan is not a compatibility promise.
