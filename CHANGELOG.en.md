## [0.4.0] - 2026-11-14

### Added

- **WinGet package information window**: the details pane now summarizes publisher, author, license, installer and release date; a new More window presents the full `winget show` metadata, tags and release notes in sections, with copy-all and URL actions.
- **Manager provenance hints**: replace verbose registration text with a glyph and tooltip; show the version-comparison hint only when a target version exists but cannot be compared.

### Fixed

- **Interactive upgrade crashes and uninstaller waits (including Pandoc)**: WinGet mutations preserve interactive installer UI; agreement snapshots belong to each task; the controller owns and safely joins workers to prevent callbacks from touching destroyed objects.
- **Clipped detail pane**: bind the information card to its parent width and clear detail state when selection resets.

## [0.3.0] - 2026-11-14

### Added

- **Package metadata on selection**: selecting any WinGet row now runs `winget show` automatically, and the details pane shows the description, publisher, license, moniker, installer type and the real homepage. A late reply is matched by exact ID rather than row number, because row numbers point at a different package after a tab switch. Previously the metadata only appeared if you pressed a button first.
- **Copy a task log**: every task row has a "Copy log" button that copies the complete redacted log (task header plus time/phase/kind/text/exit per line) and reports how many lines went out. If the clipboard is unavailable it says so instead of claiming success. A failure is exactly what someone wants to paste into an issue.
- **Keyboard operation in the lists**: the package and task lists support ↑/↓, Home/End and Enter, plus Vim's `j`/`k` and `g`/`G`; Space toggles a checkbox on the package list. Nothing is intercepted while a text field has focus. Enter used to be the only key that did anything.
- **`--focus-row` / `--hold-searching`**: two harness switches. The first selects a row without checking it, which is the only way to capture the metadata pane; the second holds the searching state so the in-box spinner can be captured. `--fake` short-circuits the search, so that animation was otherwise never visible.

### Fixed

- **The colored block next to the search box**: the hand-drawn spinner painted a `theme.layer` rectangle over the lower half of the ring. When the field's focused fill differed from the layer colour that mask became visible as a square. The spinner is now a Canvas arc with no mask, and it stays invisible-on-background across the four themes and both light/dark (captured with `--hold-searching` and inspected zoomed in).
- **An upgrade reported "success" but was graded as failure**: `update` is a documented alias of `upgrade` (visible in this machine's `winget upgrade --help`), so the verb was not the cause. The real defect was that verification only checked the package was still listed, never that it reached the target version — which is how a DBX upgrade to 0.6.70 got graded as failed. Verification now compares against the target: same or newer succeeds, still old fails and prints both versions, uncomparable never claims success. Matching is by exact ID, case-insensitively, because `winget list --id X --exact` can echo the id with different casing than the plan stored.
- **`winget show` failed outright**: the metadata lookup hard-coded `"winget.exe"`, while every other query in the plugin uses the real WindowsApps path resolved by `locateWinget()`. Under the host's environment the bare name did not resolve, and the pane only showed "The system cannot find the file specified". The lookup now uses `WingetAdapter::executablePath()`.
- **A concurrency cause behind the intermittent crash when queueing an upgrade**: the cancel flag was a `std::shared_ptr<bool>`, written on the GUI thread and read on a worker — a data race is undefined behaviour, which no amount of "intermittent" can explain away. It is now `std::atomic_bool`, with a new `RunOptions::cancelAtomic`; the platform layer accepts both pointers so the search path's `const bool*` semantics are unchanged. This does not prove the crash is gone, but it removes a real source of undefined behaviour.
- **Installed rows were hard to read**: the second line spread out `source · scope`, the version, `backend-recorded` and `版本未知`. It now shows only "manager · installed version", with an emphasised "current → target" only when an update is provable; `unknown` is hidden and provenance reads as "manager-managed" or "system record". The raw fields stay in the details pane, so no internal term appears on a row where it cannot inform a decision.

## [0.2.0] - 2026-11-14

### Added

- **Copyable exact ID**: the details pane has a dedicated ID box (monospaced, with a copy button) and the context menu offers "copy exact ID". `winget list` prints a real Id column (`7zip.7zip`, `Docker.DockerDesktop`, `ARP\Machine\X64\...`, `MSIX\Microsoft.AV1VideoExtension_...`) but inside a list it is a secondary line of text; there has to be an explicit way to take it, because hand-copying an ARP or MSIX id with its braces and backslashes is not realistic.
- **`winget show` info block**: the details pane can query the package's full metadata (version / publisher / description / homepage / license / tags / installer type and URL) and parses it into a flat key-value table. A row starts with a "Query info" button that becomes "Query again" once a result is in. ARP and MSIX rows have no manifest, so the pane explains that rather than showing an empty table.
- **The project-page button uses the real homepage**: it used to guess a search URL from the package name. Now it takes `Homepage` from `winget show` (accepting only absolute `http(s)` URLs) and opens it directly when known, otherwise it queries first. Scoop has no equivalent command, and the pane says so instead of pretending to look it up.
- **A search box on Installed**: Installed was the one tab that could not be searched, and it is the one that needs it most — nobody finds a package by scrolling through hundreds of rows. It is a **local filter** (in-memory, instant, no spinner, no skeleton rows though it shares one control with Discover's **real query** — debounced, with spinner and skeleton rows, because it starts processes).
- **The manager filter is single-select**: All / Scoop / WinGet, with only the chosen one lit. "All" is its own option rather than "both of the others", so selecting it no longer lights three buttons at once and the highlight keeps meaning "this is what you selected".
- **Discover rows can be selected and installed**: a search result is a real candidate now. Previously the rows there were not checkable, and the details pane offered disabled "upgrade"/"uninstall" buttons for a package that is not installed — two operations that cannot exist for it.
- **Actions follow the row's state**: the details pane, the context menu and the selection bar offer only what that row can actually do. Not installed → install + project page; installed → upgrade (when a newer version exists) / uninstall + project page.
- **Project page**: any row can open its project page (Scoop via the scoop.sh search page, WinGet via a GitHub repository search). When looking up a package that is not installed yet, reading about it is often the right next step instead of installing it.
- **Task rows can be selected**: clicking a task selects it, with a left accent bar and a subtle fill, and the status line names it ("selected <target>"). The row used to be deliberately inert (`acceptedButtons: Qt.NoButton`), which left "which task am I about to cancel" to be guessed from position.
- **`--fake` populates search results and the four task states** (running / queued / succeeded / failed). Without them those surfaces were empty with no backend, so they could not be checked at all.
- **Search feedback**: a spinner inside the search box and skeleton rows in the list. A search takes seconds, and during that time the list was empty — which reads as "nothing found" rather than "still looking". One small line in the status bar was too easy to miss.
- **Discover is decoupled from Installed**: Discover no longer falls back to the installed inventory when the box is empty (that made the tab look like a copy of Installed). A new 结果/Result filter offers Not installed (default) / All / Installed. Installed matches are hidden by default because the point of searching is to find something new.
- **Installed can be filtered by source**: a new 来源/Source filter offers All / Managed / Installed by you. A manager-owned package is one the backend records as its own; a "user" row is an ARP/MSIX entry it merely observed. They are not the same thing, and mixing them in one list cannot answer "which of these can this plugin actually manage".
- **Per-row context menu**: right-clicking a row offers the actions that row can take (details / copy exact ID / upgrade / uninstall / install / add to selection). Acting on one package used to require checking it and then using the multi-select entry point — a multi-select gesture for a single-item operation. The items come from the model's capability fields, so a row with no newer version does not offer an upgrade.
- **Multi-select actions moved above the list**: the selection bar sits directly above the rows and reports "Selected N · X upgradable · Y installed (removable)" with review and clear buttons. The status bar no longer holds buttons — a status bar is read as output, and a button there is both easy to miss and far from the rows it acts on.
- **`--select` / `--discover-filter` / `--search` / `--detail-action` / `--installed-filter`**: five harness switches so the selection bar, the Discover filter, the search animation, the details-pane action path and the Installed filter can each be driven and captured without a mouse. `--detail-action` reproduces the crash path above in one command.
- **Development tool `packages_dev.exe`**: opens the same window without the host, linking exactly the same Controller, models, adapters, platform layer and QML scene. `--style/--theme/--size` switch appearance, `--fake` uses deterministic data, `--simulate-elevated` reproduces the elevated environment, only `--data-dir real` touches the real cache, `--plan` prints argv only, `--lint` checks layout. `run-dev.ps1` builds and launches in one command. It is **not shipped** (absent from the `package.py` allowlist) and `packages.exe` has none of these switches. See `docs/dev-harness.md`.
- **`--lint` layout check**: encodes the defects that actually happened as three rules — a container with no painting ancestor (shows white under dark themes), a child wider than its parent, and excessive spacing between 管理器 and the segmented buttons. Exits 1 when it finds one.
- **`--expect-rows` cache assertion**: checks the model row count before the event loop starts, when no backend reply can have arrived, so the rows can only have come from the disk cache.
- **`--review` and `--shot-delay`**: the review page is state-driven and can only be checked with a switch that opens it; a real backend needs over ten seconds, so a capture needs a controllable delay.
- **`check-layout.ps1`**: runs `-Lint` over 6 pages × light and dark, 12 cases, exit 1 if any fails. Every layout defect here shares one property — a code review does not catch it and a screenshot misleads — so a check a script can run beats looking carefully.
- **Themed button `ThemedButton.qml`**: the QtQuick Controls Basic style paints a default button as a light plate, which is an unreadable bright block under a dark theme. Every button now goes through one component with `primary`/`danger` emphasis.
- **Per-task intervention**: each task row shows its own buttons for its own state (queued → Start / Remove, running → Cancel, failed/cancelled/interrupted → Retry / Remove, succeeded → Remove), all addressed by task id. The two previous buttons acted on "the last matching task", so clicking row 1 could operate on row 5.
- **Queue controls**: the Tasks header has pause/resume, clear finished and rescan. Pausing only stops the queue from picking up the next task; the running one continues (cancelling is a separate, explicit action).
- **Per-step task log**: every task records time / phase / text / exit code, expandable inside its row. All text is redacted before it is stored (`%USERPROFILE%` substitution, ANSI stripped, suspected secrets dropped), capped at 200 entries keeping the tail, and kept in memory only.
- **Review action picker**: upgrade and uninstall are independent intents, so the user chooses instead of the plugin inferring one; switching recomputes method, material, verification, risk and agreement requirements. An uninstall has no source or installer agreement and only asks for an impact acknowledgement.
- **Queue executor**: confirming a plan now actually runs it — each task goes through `buildMutation` (the single argv builder) → `platform::run` → `verifyInstalled` (exit code 0 is not success) → `queue.finish`; the acquire/install/verify phases are visible on the Tasks page; cancel terminates the job and the task says it is not a rollback; a finished run refreshes the inventory automatically.
- **Scoop update listing**: compares the local bucket manifest's `version` (`%SCOOP%\buckets\<bucket>\bucket\<app>.json`) against the installed version — a pure file read that never runs `scoop status` and never syncs buckets; the Updates tab has its own snapshot and timestamp.
- **Disk cache**: the last successful scan is written to `%LOCALAPPDATA%\WinShun\plugins\ra9fael.packages.data\cache.json` (atomic write), so a restarted plugin paints rows immediately and only re-queries once the data is older than `refreshMinutes`.
- First development preview: `pkgs` (instant) opens the Packages window, `packages <words>` searches; with Installed / Discover / Updates / Tasks.
- The manager filter is a multi-select segmented control: Scoop and WinGet toggle independently and may both be off (the list then shows a "both managers are hidden" state); 全部 is itself a toggle (both on ↔ both off).
- Declares the `elevated` permission: the plugin follows Win顺's administrator state once the user confirms it in the host settings. When elevated, machine/global-scope changes can reach preflight; when not, those scopes are blocked at preflight with the reason, and the title-bar rights chip reports the real runtime state.
- WinGet read-only queries (list / search / upgrade-available / pin list), parsed behind fixtures captured from real v1.29.380 zh-CN output; versions that reject `--output` honestly fall back to table parsing.
- Scoop read-only queries (export JSON / search sectioned text / status holds), through the fixed trusted `scoop.ps1` entry with a strict argv whitelist.
- UI style follows Win顺: every `nativeLook` token (fluent / brand / tactile / liquid × light/dark), the rounded/square setting, and the four 界面大小 tiers; translucent tokens are composited onto the base as the docs require.
- Pure-core L1 tests (identity / version / plan / queue / queue intervention / redaction / theme tokens / disk cache), real-backend fixture tests, real-child L2 process tests, and L0 static validation (manifest shape, bilingual doc links, x64 PE).

### Fixed

- **Discover did not recognize installed packages**: a search result whose exact ID matches an installed package (case-insensitively, source and scope excluded) now carries that package's installed version, provenance, upgrade target and uninstall capability. Neovim's `Neovim.Neovim` result therefore shows 0.12.6 and offers Uninstall, while genuinely absent results keep offering only Install. The candidate's own source/ID stays intact. Verified by `packages_dev.exe --fake --search neovim --tab-cycle-check`.
- **Switching tabs cleared Discover**: `setTab()` emptied the query text and the search snapshot whenever Discover was left, so returning to Discover showed an empty list even though the search had succeeded (and an in-flight result was dropped). Each tab now owns its query state: Discover's text and results survive round trips, an in-flight search still lands into its snapshot, and emptying the Discover box is the explicit way to clear it. The same rule applies to the other tabs — Installed's filter, Updates' listing and the queue state are never discarded on tab change. The status line only reports "Searching…" while Discover is active. The harness's new `--tab-cycle-check` asserts both behaviors.
- **The Updates tab was empty after every restart**: `saveCache()` wrote only the installed snapshot, so the update listing was never persisted. Every restart therefore had to wait for `winget list --upgrade-available` plus a bucket scan (tens of seconds) before that tab could be used, showing an empty page and "not scanned yet" in the meantime. The update listing is now stored in the same `cache.json` (written in one pass, so a crash between two writes cannot leave one behind), with its own `updatesAt`: it is a different query and must not share the inventory's timestamp. Measured: after one cold scan the cache holds 17 update records, and the next warm launch passes `--expect-rows 14` before the event loop starts (3 of the 17 carry a target shaped like `< 2026.3.1`, which cannot prove an upgrade, so that tab does not list them).
- **A restarted window reported "Query limited" while it was healthy**: `statusLine()` treated "any state pane is showing" as "the query failed", but Discover's "type a keyword to search" and "every match is installed" are ordinary answers. Landing on Discover with an empty box after a restart therefore described a working window as a broken one. Only `backend-missing` / `unsupported` report 查询受限 now; Discover says 尚未搜索 / 搜索完成 · N 个结果 / 匹配项全部已安装, and "no matches" is a different answer from "every match is installed".
- **The Tasks header said "idle · 0 active" above a list of four tasks**: the counts read the core queue's `m_queue.tasks()`, while the harness's `--fake` fed only the model. `--fake` now injects the queue too, so the tab badge, the header and the status line agree.
- **Every `--fake` screenshot said "Querying…" in the status line**: `openWindow()` starts a real scan when the cache is stale, so a deterministic capture described a window still waiting on a backend. New `setFakeMode()` short-circuits both the scan and the search, leaving the injected snapshot as the only source of the window's content. `--fake` also injects before opening the window now; the other order triggered the scan as well.
- **`--detail-action` could never run against a real backend**: it acted when the window opened, before the scan had returned, and reported `row 0 out of range` — so the switch written to reproduce the crash could not run against real data even once. It now waits for the row to appear (250 ms poll, 60 s cap, and a loud failure instead of a silent exit 0).
- **The exact ID in the details pane was always `—`**: the QML asked for `key: "id"`, but `PackagesModel::fieldAt()` only knows `"exactId"`, and an unknown key silently returns an empty string. The ID is the only reliable identity in an install/uninstall/upgrade command line, and that was precisely the row that rendered blank. It now uses `exactId`.
- **Checking a row and pressing upgrade crashed, and afterwards queries were "limited"**: `DetailPane` and the context menu both called `setReviewAction(action)` **before** `openReview()`. At that moment `m_reviewActions` is still empty (the action table is filled by `openReview()`), so `setReviewAction` returned early and the review opened with no requested action, then walked the confirmation path with an empty action. One layer deeper: `openReview()` requires exactly one **checked** row (`singleCheckedRow()`), and the details pane had only **selected** it. Everything now goes through one `openReviewFor(row, actionId)`: clear checks → check that row → `openReview()` → `setReviewAction()`. Measured: `--detail-action 1:upgrade` went from `actions=0 action=` to `actions=2 action=UPGRADE confirm=no`.
- **The search box kept spinning after a finished search**: `searching()` is `m_searchInFlight || m_searchPending`, and `applySearchResults()` had an early-return branch (stale result, or the tab had moved on) that returned without clearing `m_searchPending`. All three exit paths clear it now.
- **Discover's "not installed only" did not exclude installed packages**: `isInstalled()` compared the full `PackageKey` (manager + source + id + scope). `winget list` prints no source for ARP rows and always reports scope `unknown`, while `winget search` fills both differently, so nothing ever matched and "not installed only" was the same as "all". It now compares manager + id, case-insensitively (`winget list` and `winget search` do not always agree on casing).
- **Searching in Discover could leave it stuck on "query limited"**: with the two bugs above, a search that was discarded or navigated away from never returned to a clean state. `setTab()` now emits `searchStateChanged()`, so leaving the tab ends the visual wait immediately.
- **The Tasks selection and the status line disagreed**: each task row offered its own state-appropriate buttons, but the row itself could not be selected and `selectedTaskLabel` was never set. Clicking a row now selects it, and pressing one of its buttons moves the selection to that row.
- **The manager filter's "both off" state no longer exists**: multi-select allowed turning Scoop and WinGet both off, which needed a `managers-hidden` state pane to explain the resulting empty list. Single-select removes the state, so the pane and its strings are gone.
- **The details pane kept describing the previous tab's row**: `ListView.currentIndex` survives a model reset. Switching tabs, starting a search and a model reset now clear the selection.
- **Scoop search never returned anything**: two independent causes stacked.
  1. Scoop 0.6.0 changed `search` output from grouped sections (`'main' bucket:` + `name (version)`) to a table (Name / Version / Source / Binaries), and the parser only understood the old shape, so every row was skipped. Both shapes now parse; column starts come from the header (the widths depend on the longest name, so hard-coded offsets would break) and the `Binaries` column bounds `Source`.
  2. The subtler one: when `scoop.ps1` is invoked through `powershell -File`, PowerShell's formatting subsystem is not attached to the pipeline, so a command that emits *objects* (`scoop-search` emits a table) prints only its own header and the rows are lost. Measured: `-File` returned 32 bytes (`Results from local buckets...`), `-Command` returned 964 bytes / 14 rows. It now uses `-Command "& '<shim>'"`.
- **A search typed before the first scan finished stayed empty forever**: both adapters refuse while the probe is `Unknown`, and nothing retried. The search is now deferred until the probe is known, and the scan completion starts it.
- **A warm cache deferred the search indefinitely**: `openWindow()` skips the scan when the cache is fresh, so the probe stayed `Unknown` forever. `loadCache()` now restores each backend's state, so the probe is known without running one.
- **The details pane kept describing the previous tab's row**: `ListView.currentIndex` survives a model reset. Switching tabs and starting a search now clear the selection, and the list resets `currentIndex` on a model reset.
- **The status bar said "Querying…" during a search**: `m_busy` (the background scan) outranked the search state, and the scan may have been running since the window opened. A search is what the user just did, so it is reported first.
- **Rows with no update showed `→ —`**: the `available` field returns `—` rather than an empty string when there is no target version, and the version block treated that as a value. `—` is now treated as absent, so only the installed version is shown.
- **The disk cache never actually took effect**: `loadCache()` runs in the constructor, and its final `rebuildRows()` returns immediately while `m_packages` is still null — the model is not attached at that point. The cache was read into memory and never turned into rows, so a cold start painted an empty list and only the refresh button brought data back. That is the other half of "it queries again every time I open it". `attachModels()` now rebuilds once after attaching the model. Verified with `packages_dev.exe --expect-rows` (which checks the row count before the event loop starts): a cold start paints 373 rows straight from the cache.
- **The middle pane showed white under a dark theme, and the whole Tasks page did too**: `SplitView` is not a `Control` — it has no `background` slot (the assignment is silently ignored) and paints nothing itself; `TasksPage`'s root was a bare `Item`. Both exposed the white layer beneath. The `SplitView` is now wrapped in a `Rectangle` painted with `theme.page` and defines `handle:`, and the `TasksPage` root is a `Rectangle` with a `color`. Rule 1 of `--lint` is exactly "every visible container has a painting ancestor".
- **The search field and the review page's check boxes were still bright plates under a dark theme**: the same root cause as the buttons — the QtQuick Controls Basic style does not follow the host theme, so a `TextField` is a white panel and a `CheckBox` is a light square. Added `ThemedField.qml` and `ThemedCheckBox.qml`, and the review page's action picker now uses `ThemedButton` too. There is no longer a bare `Button`, `TextField` or `CheckBox` anywhere in the QML.

- **Scoop was not found (`scoop.ps1 was not found at C:\Users\Default\scoop\shims`)**: the plugin located Scoop with `%USERPROFILE%`, but the host starts an elevated plugin with a clean environment (system variables plus `FOLDERID_Profile`), and that known folder resolves to `C:\Users\Default` when no user profile is loaded — so the search went to a directory that does not exist. It now resolves in this order: `%SCOOP%` → the **registry `ProfileList\<SID>\ProfileImagePath` for this process token** (never `USERPROFILE`) → `scoop.ps1` on `PATH` (the parent of its `\shims\` is the root) → `%ProgramData%\scoop`, and the failure text says which step supplied the root. A real `scoop export` was run in both the normal and a simulated elevated environment (`USERPROFILE=C:\Users\Default` with scoop removed from `PATH`): both returned the same 6 packages.
- The cache treated "backend unavailable" as fresh data: after the fix above, a stored `scoop: missing` would still be shown for up to `refreshMinutes`. Opening the window now re-scans whenever any backend is not `Ready`, so a failure is never reused as a result.
- The task list could only be watched, not managed: none of the three operations took a task id (`removeLastPendingTask` / `requestCancelLastRunning` / `retryAction`), and removing deleted "the last removable task". All operations are now by id and the buttons follow the row's state.
- **Installed rows could not be selected, could not be uninstalled, and every plan failed**: three symptoms, one cause chain, from two separate bugs stacked on top of each other.
  1. `winget list` prints no scope, so rows have `unknown`; but `WingetAdapter::buildMutation()` called `isResolvable(key)` with its default argument (scope required), so **every real run was refused** with `identity is not exactly resolvable` — the direct cause of the Tasks page's `计划都失败`. Only install passes `--scope` now, so only install requires one; upgrade and uninstall match by exact id.
  2. `fromListText` set `canUninstall` to `false` unconditionally, while `canUpgrade` depended on an available version `winget list` does not provide — so all three flags were false, `actionable` was false, and the checkbox was `enabled: false` at 35% opacity: **the whole Installed page was inert**. An installed non-ARP row is now removable, and a refresh merges each update's target version onto the matching installed row by exact identity so it can be upgraded directly too.
  3. Update rows (WinGet upgrade list and Scoop bucket manifests) also never set `canUninstall`; that is fixed too.

  Real evidence: `isOfficeAI.OfficeCLI` (scope `unknown`, installed 1.0.158) is now selectable, opens the uninstall review, and reaches a confirmable state; the built `winget uninstall` argv contains no `--scope`.
- There was no way to reach an uninstall: the review page inferred one action by rule, so an installed package with an update available was always an upgrade. It is now a picker whose legal actions come from the row's real state.
- An excessive gap (measured at 137 px) between the 管理器 label and the segmented buttons: the segmented control used `Layout.preferredWidth: implicitWidth` while its inner `Row` was `anchors.centerIn: parent`, and `RowLayout` mis-measures that pairing — the width can depend on content, while the content depends on the parent width — producing an implicit width far larger than reality. It now uses a `Row` (which lays children out at their real widths) with an explicit `width`/`height` on the segmented control. The hidden search field reserving space was a second contributor and is fixed too.
- The Tasks footer reported "read-only query complete" and showed "Selected 0 / Review selected…": the status text depends on the tab but `setTab` never re-emitted it, and selection is a list-page concept. The Tasks footer now reports the queue and hides the selection controls.
- The task log panel was unreadable in dark mode: it used a non-existent token `theme.controlFill` (undefined → transparent → white underneath). It now uses `theme.control`, and a check asserts every `theme.*` reference resolves.
- `winget pin list` ran twice per parallel refresh, and so did `scoop export`: the installed and updates queries each called them. Each now has one mutex-guarded cache per scan, invalidated explicitly at the start of every refresh (shared inside a scan, never across scans); `verifyInstalled` still bypasses the cache, otherwise the check would read the pre-run state.
- Nothing could be updated/installed/uninstalled: the queue had only a state machine and no executor, so a queued task waited forever. The executor is implemented (see Added) and the material preflight is unblocked — winget/scoop fetch their own material, the plugin neither prefetches nor verifies it, and the review page says so.
- Search bled across tabs: the query was passed to every tab as a filter. Each tab now has its own data source (installed / search results / update list) and its own filtering semantics; search applies to Discover only, the box is cleared on leaving it, and it is only shown there.
- The scoop update list was empty: the Updates tab reused the installed snapshot, and `scoop export` carries no available version. It now compares the local bucket manifest `version` (a pure read) with its own snapshot and timestamp.
- Every launch re-scanned: the cache lived only in memory. A successful scan is now written to disk and loaded first, and nothing re-queries within `refreshMinutes`.
- Typing in Discover froze the window (Not Responding): the search ran `winget` synchronously on the GUI thread. It is now a worker thread (single-flight, stale results dropped) behind a 500 ms debounce.
- High memory use: the freeze stacked one winget child per keystroke. Asynchrony removes it, and leaving Discover drops the search snapshot.
- The state pane text was not centred: `Layout.alignment` does nothing for a Text wider than the pane, so it now uses `fillWidth` + `horizontalAlignment`.
- Upgrade could not be performed from the Updates tab: `winget list` prints no scope column, so rows had an unknown scope while the identity gate demanded a known one. Only install needs a scope; upgrade/uninstall match by exact id.
- `winget --version failed (exit 0)`: `run()` left the loop without a final pipe drain, losing a fast child's output.
- Every fixed-height bar collapsed to 0 and content overlapped: a context property named `Theme` (QML resolves a capitalised name as a type) plus a `themeResolver` that was not visible when Theme.qml was created silently killed every binding.
- Settings popup text overflowed: the ColumnLayout had no bound width, so `wrapMode` had nothing to wrap against.

### Safety and boundaries

- Never generates `winget reinstall` (the verb does not exist), never treats `repair` as reinstalling, and never passes `scoop update --force` / `reset` off as a reinstall.
- Never auto-accepts a source or installer agreement; option-like ids, URLs and scripts are refused as identities; no shell command is ever concatenated.
- Never asks for elevation on its own: `elevated` only follows the host's administrator state, presented and confirmed by the host settings page; the plugin never raises UAC.
- Install/upgrade/reinstall stop at preflight (material prefetch is not implemented, and the design forbids "uninstall first, then look for the package"); uninstall can reach confirmation. The executor and the review action picker are implemented and covered by L1 tests; no mutation was executed for real on a developer machine during development, so the run path is verified by fixture/L1 evidence rather than by a live install.

### Known limitations

- liquid's Acrylic/Mica backdrop is not replicated in the plugin window (the plugin cannot obtain the host's DWM backdrop); the composited opaque palette is used instead.
- The appearance pipeline is not yet verified inside the real host process; a round after host integration is still needed.
- The process hangs on exit after `app.exec()` returns (a suspected local Qt environment issue; the host ends plugin processes via its job, so integration is unaffected).
