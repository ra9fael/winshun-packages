# 0.4.8 local validation — WinGet profile mismatch

WinGet's diagnostic log showed the exact split causing the uninstall failure:

```text
installed.db -> C:\Users\renfei\...
Dufs portable DB -> C:\Users\Default\...
```

The plugin process inherited a sanitized `USERPROFILE`, while its token still
belonged to `renfei`. `winget list` could read the installed index, but the
portable uninstall opened the Dufs database under `C:\Users\Default` and got
`0x87AF0008`.

`RunOptions.environment` was also previously constructed but never passed to
`CreateProcessW`. It now is. WinGet children receive `USERPROFILE` derived from
the current process token using `GetUserProfileDirectoryW`, avoiding the stale
environment value. No package was uninstalled during validation.
